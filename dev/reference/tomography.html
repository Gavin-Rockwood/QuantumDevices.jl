Model tomography ​

QuantumDevices.Measurement Type
julia
Measurement(effects::AbstractVector; labels=eachindex(effects), acts_on=nothing, atol=1e-8)
Measurement(observable::AbstractQuantumObject; acts_on=nothing, atol=1e-8)

An ordered, complete POVM. Effects must be Hermitian positive operators summing to identity. An observable is converted to projectors onto its distinct eigenspaces, ordered and labeled by eigenvalue (degeneracy tolerance atol). acts_on selects ascending, unique, one-based tensor subsystem indices; otherwise effects act on the full retained state. Leakage requires an explicit outcome. Outcome labels describe vector order, not array indices.

QuantumDevices.SequenceData Type
julia
SequenceData(sequence, preparation, measurement; counts=nothing,
             probabilities=nothing, shots=nothing)

Measured outcomes following named gates in execution order. Supply a normalized ket/density matrix or model -> state preparation, and a Measurement or model -> Measurement. Exactly one distribution input is required, in the measurement's outcome order. Counts are nonnegative integers with positive total; shots are inferred. Probabilities may optionally carry a positive integer shot total, and are preserved without rounding into counts. Input vectors are copied.

QuantumDevices.ModelTomographyProblem Type
julia
ModelTomographyProblem(model, paths; predict, observed, uncertainty=1, loss=:auto, kwargs...)
ModelTomographyProblem(model, paths; sequences, preparation, measurement, observed=nothing, counts=nothing, shots=nothing, kwargs...)
ModelTomographyProblem(model, data, paths; loss=:auto,
    probability_floor=1e-12, evolution_kwargs=(; abstol=1e-8, reltol=1e-8), threaded::Bool=false, subspace=nothing, leakage_outcome=nothing,
normalize::Bool=true, parameter_scales=nothing, scale_function=nothing, lb=nothing, ub=nothing, threaded_components::Bool=true, normalize_probabilities::Bool=false, reference_model=:initial, tracking_steps=0, kwargs...)

For sequence fits, pass plain sequences and shared preparation/measurement with exactly one of observed probability vectors or counts vectors, ordered by sequence and measurement outcome. Optional shots is a shared integer or a vector in sequence order (entries may be nothing). Counts infer their shot totals. Do not mix scalar predict with sequences. Existing per-record inputs remain available for experiments with different preparations or measurements.

Fit finite real model/gate scalars selected by writable slash paths. Accepts SequenceData records, or a scalar predict(model) function and an observed NamedTuple. Scalar predictions must return a NamedTuple with exactly the observation names, in any order. Values must be finite real scalars. uncertainty is a nonnegative scalar (default 1) or a NamedTuple with those names. Zero uses an unweighted residual for that observation, rather than division by zero or an exact equality constraint. Residuals follow observation order. Exposes a standard SciML optimization .problem, immutable .rebuild(values), and .paths. Solve using solve(setup, algorithm; kwargs...); no optimizer is selected here. By default normalize=true uses physical = initial + scale .* coordinates, with zero optimizer initial coordinates. Scales are absolute initial values, or 1 for zero-valued parameters. parameter_scales overrides scales in path order, or scale_function(path, initial_value) supplies them. Scales stay fixed. Bounds are supplied in physical units and transformed automatically. With normalize=false, optimizer coordinates are physical values. Use physical_parameters to interpret solution.u; .rebuild and tomography_residuals consume optimizer coordinates in both modes. Candidate values are applied together: each changed component is reconstructed once. Physical candidates use make_model; no incremental model cache is kept. threaded_components=true reconstructs changed components concurrently on Julia threads. Set it to false for serial reconstruction; custom component constructors must be thread-safe. Gate-only candidates reuse the idle model. reference_model=:initial and tracking_steps=0 match each candidate once against the fixed initial eigenbasis, transporting rebuilt component bases for physical overlaps. Positive tracking steps add intermediate models. Automatic initial references fall back to bare tracking when no compatible basis transport exists; explicit references must be compatible. Set reference_model=nothing, tracking_steps=18 for the original bare-state tracking. Physical rebuilds do not inherit gates. Sequence fits with nonempty gates require an explicit gates dictionary. Selected gate paths update that dictionary independently of physical reconstruction. Every candidate starts from the input model, independently of earlier optimizer evaluations. Paths must resolve to distinct writable destinations; aliases and overlapping paths are rejected. loss=:auto selects :likelihood when every record has shots and :least_squares when none does. Mixed shot-qualified sequence datasets require explicit :least_squares. Scalar datasets always use least squares, with residuals (predicted - observed) / uncertainty for positive uncertainty, or the raw difference for zero uncertainty. They reconstruct each candidate once and evaluate all predictions without gate evolution. Likelihood is summed multinomial negative log likelihood without constants; probabilities with shots use -N*sum(f .* log(p)), without rounding counts. Only logarithms use probability_floor; zero-count terms contribute zero. Least squares sums squared outcome-probability residuals without observable- variance weighting. Additional keywords, including bounds, pass to SciML. threaded=true builds distinct gate propagators in parallel on Julia threads; it and evolution_kwargs have no effect on scalar fits. subspace and leakage_outcome enable projected sequence fitting as described by predict_sequence. normalize_probabilities=true normalizes predicted outcome weights after complementary leakage is assigned; the default false retains strict validation. This option has no effect on scalar fits. For sequence fits, diagnostics=report -> ... receives per-prediction wall-clock timings in seconds: rebuilding, gate updates, input setup, propagation (including per-gate pairs), and sequence/measurement evaluation, plus physical parameters. Constructor validation is included; first calls may include compilation. The callback runs after prediction and is excluded from the reported total. Shared controls and solver callbacks must be safe for concurrent calls. Automatic differentiation is not guaranteed through model reconstruction.

QuantumDevices.predict_sequence Function
julia
predict_sequence(model, sequence; preparation, measurement, kwargs...)
predict_sequence(model, sequence, preparation, measurement;
    evolution_kwargs=(; abstol=1e-8, reltol=1e-8), threaded::Bool=false, subspace=nothing, leakage_outcome=nothing, normalize_probabilities::Bool=false, gates=model.gates)

Predict ordered outcome probabilities without observed data. Preparations and measurements may be fixed objects or functions of the candidate model. Gates use their local time origins, full retained-space unitaries, and existing frequency units. Empty sequences measure the preparation; zero-duration gates are identity. subspace may be an ordered orthonormal ket vector or model -> vector. Only those columns evolve in the full Hamiltonian; each gate is projected to the basis before multiplying sequences. This approximation discards leakage return. Preparations must lie in the basis. To preserve discarded probability, supply leakage_outcome indexing the complementary measurement effect that annihilates the basis. Lost population is an absorbing outcome, never renormalized away. normalize_probabilities=true normalizes finite nonnegative outcome weights at measurement, after assigning discarded population to the complementary leakage outcome. It does not normalize projected states or permit unaccounted population loss when no leakage outcome is supplied. Negative weights beyond rounding tolerance still raise an error. The default false retains strict checks. With normalize_probabilities=false, full-space evolution corrects normalization drift of at most 1e-6 after each gate; larger drift is rejected. Projected population loss is preserved. gates explicitly selects the gate dictionary (default: model.gates). Native solver options pass through evolution_kwargs. Set threaded=true to build distinct gate propagators in parallel on Julia threads. Shared controls and solver callbacks must be safe for concurrent calls.

QuantumDevices.predict_sequences Function
julia
predict_sequences(model, sequences; preparation, measurement, kwargs...)
predict_sequences(model, data; evolution_kwargs=(; abstol=1e-8, reltol=1e-8), threaded::Bool=false, subspace=nothing, leakage_outcome=nothing, normalize_probabilities::Bool=false, gates=model.gates)

Predict directly from a list of gate sequences using shared preparation and measurement objects or callbacks; no observed data is required. Alternatively, pass SequenceData records; their observed distributions are ignored. Return probability vectors in input sequence order. Each required gate propagator is computed once per call and reused across records. Repeated preparation and measurement objects are resolved once per call by identity. subspace and leakage_outcome follow predict_sequence: projected matrices are computed once per required gate; discarded population cannot return. No caches survive between candidate models. Inputs are not modified. Optional diagnostics=report -> ... receives seconds for setup_seconds, propagation_seconds, sequence_seconds, total_seconds, and gate_seconds (gate-name => seconds pairs). Threaded gate times overlap. Callback execution is excluded from the total; callback errors propagate. threaded=true parallelizes propagator construction only; shared controls and solver callbacks must be safe for concurrent calls.

reconstructed_model(problem::ModelTomographyProblem, values)

Rebuild a fitted model from optimizer coordinates, e.g. solution.u, without modifying the input. Normalized coordinates are rescaled automatically. Inspect the optimizer retcode and fit quality before accepting its values.

QuantumDevices.tomography_residuals Function
julia
tomography_residuals(problem::ModelTomographyProblem, values)

Return prediction-minus-observation residuals in dataset and outcome order. Inputs are optimizer coordinates, rescaled before predicting observations. For scalar fits, residuals follow observation order and are divided by positive uncertainty; zero uncertainty leaves the residual unweighted. Only available for least squares; their squared norm equals the scalar objective. External residual-based solvers may call this function directly.

Data and losses ​

Sequence prediction uses plain sequences and shared settings:

julia
observed = predict_sequences(target, sequences; preparation, measurement)
problem = ModelTomographyProblem(initial, paths;
    sequences, preparation, measurement, observed, gates=initial.gates)

observed is one probability vector per sequence, ordered by measurement outcome. For integer counts, use counts=measured_counts instead; do not provide both. shots can be a shared positive integer or a vector matching the sequences. Vector entries may be nothing; mixed shot qualification requires explicit loss=:least_squares. Counts infer totals and check any supplied shots. predict_sequence(model, sequence; preparation, measurement) handles one sequence. Prediction requires no observed distributions. Retain SequenceData and the three-argument problem constructor for per-experiment preparation or measurement. Do not mix scalar predict with sequences.

Scalar fitting uses ModelTomographyProblem(model, paths; predict, observed, uncertainty=1). observed must be a nonempty NamedTuple. predict(model) is called once per evaluation and must return a NamedTuple with exactly the same names; ordering may differ. Each value must be a finite real scalar. Residuals follow the observation order.

uncertainty is a common nonnegative scalar, or a NamedTuple with one nonnegative uncertainty for every observation. For example, use uncertainty=(ge=0.001, ef=0.002) with observed=(ge=4.8, ef=4.6). Zero uncertainty leaves that observation unweighted; it does not impose an exact equality constraint. Thus uncertainty=0.0 gives unweighted least squares, like the default of 1. Predictions, observations, and uncertainties must use the same units; errors are independent. loss=:auto and :least_squares both minimize uncertainty-scaled residuals.

For SequenceData, counts infer their shot total. Probabilities may include shots without rounding into reconstructed counts. Keep observations in the measurement's outcome order; labels are not array indices. loss=:auto uses multinomial negative log likelihood when every record carries shots, and unweighted least squares when none does. Mixed shot-qualified records require explicit loss=:least_squares; shot totals do not weight that loss. Likelihood omits parameter-independent constants and uses probability_floor only inside logarithms. Zero-count terms contribute zero.

tomography_residuals(setup, values) is available for least squares; its squared norm equals the objective. Scalar and direct sequence fitting share the two-argument constructor.

Measurements and prediction ​

Use Measurement(effects; labels=..., acts_on=...) for a complete POVM or Measurement(observable; acts_on=...) for eigenspace projectors. Degenerate observable eigenstates share an outcome. Effects must sum to identity; include leakage as additional outcomes. Subsystem indices are one-based and ascending. Preparations can be kets, density matrices, or functions of the candidate model. Measurements can also be functions returning Measurement.

Fixed states and effects are interpreted in the candidate's retained component basis. They are not automatically transformed from an external laboratory basis. Use model-dependent functions when physical updates require regenerating them.

predict_sequence needs no observed data. predict_sequences ignores observed distributions and shares each required gate propagator across all records in that call. Gate clocks reset at each gate's local origin; empty sequences measure the preparation directly. No propagator cache survives between candidates.

Solver options ​

Bounds such as lb and ub go to ModelTomographyProblem; select an optimizer that supports them. Optimizer settings and callbacks go to solve. The wrapper returns the native SciML solution. Automatic differentiation through physical reconstruction is not guaranteed; derivative-free optimization is a useful start.

threaded=true builds gate propagators concurrently. Shared controls and solver callbacks must be safe for concurrent calls. evolution_kwargs forwards native ODE solver settings. Both options affect sequence fits only. Selected slash paths must refer to distinct writable scalar inputs; aliases and overlapping paths are rejected. Inspect solver retcodes, held-out predictions, other initial guesses, and dressed-state tracking confidence before accepting a fit. Low loss does not establish unique parameter recovery.

Projected sequence fitting ​

Supply subspace as an ordered orthonormal ket vector or a function returning one for the candidate model, for example:

julia
subspace = m -> [m.states[label] for label in ((0,0), (1,0), (2,0))]
setup = ModelTomographyProblem(model, data, paths;
    subspace, leakage_outcome=4, threaded=true)

Only the selected columns are integrated in the full Hamiltonian. The projected gate matrices are cached once per candidate and multiplied to evaluate sequences. The preparation must lie in the supplied basis. Projection after each gate loses paths that leave the basis and later return; compare against full-space predictions and enlarge the basis when needed. This option applies to sequence fits only.

leakage_outcome is a one-based index into each measurement's ordered effects. That effect must be the complement of the subspace projector. Discarded probability is assigned to this absorbing outcome without conditioning on survival. Without it, appreciable discarded probability raises an error. predict_sequence and predict_sequences accept the same keywords. The default subspace=nothing retains full-space evolution.

Parameter normalization ​

Fits default to dimensionless optimizer coordinates, with physical = initial + scale .* coordinates. Initial coordinates are zero; scales are absolute initial parameter values, or 1 for zero-valued parameters. Use parameter_scales=[...] in path order to set characteristic changes, or scale_function=(path, initial) -> .... Scales must be finite and positive and are fixed for the entire fit. Choose an explicit scale for small shifts starting at zero. Parameter scaling does not change observation uncertainty weights.

solution.u, residual inputs, and reconstruction inputs are optimizer coordinates. Use physical_parameters(setup, solution.u) to report physical values. Bounds lb and ub are supplied in physical units and transformed for the optimizer. Set normalize=false to use physical coordinates directly. Optimizer simplex sizes and coordinate tolerances use the chosen coordinates; objective tolerances such as g_abstol keep their existing meaning.

Component reconstruction uses threaded_components=true by default in both tomography constructors, independently of threaded gate propagation. Changed component constructors run concurrently when multiple components change and Julia has multiple threads. The normal builder assembles operators and tracks dressed states using the requested reference and intermediate steps. Use threaded_components=false for serial reconstruction or custom constructors that are not thread-safe. Start Julia with --threads=auto to enable workers.

With normalize_probabilities=false, full-space prediction corrects small state-normalization drift (at most 1e-6) after each gate, preventing accumulation when a numerical propagator is reused many times. Larger per-gate errors raise an error asking for tighter evolution tolerances. Projected-subspace leakage is never normalized away.

Use normalize_probabilities=true in prediction or sequence tomography to normalize finite, nonnegative predicted outcome weights. Projected missing population is assigned to the complementary leakage outcome first, preserving physical leakage. Projected loss without a leakage outcome still raises an error, as do negative weights beyond rounding tolerance, non-finite weights, or zero total weight. The default false retains strict normalization checks. This differs from normalize, which scales optimization parameters. Probability normalization does not correct integration errors in relative phases or outcome proportions.

Reconstruction and state references ​

Every physical candidate uses make_model, without an incremental reconstruction cache. Tomography defaults to reference_model=:initial, tracking_steps=0: one candidate diagonalization, matched to the fixed initial eigenbasis. Transmon basis maps carry overlaps into the same physical charge basis after EC/EJ changes. Reference states are not frozen and energies always come from the candidate. tracking_steps=N adds N intermediate models along numeric parameter changes; model structure must stay fixed. Confidence is accumulated squared physical overlap along this path; it is not a correctness probability. Inspect it and increase steps near avoided crossings. Candidate evaluation order has no effect. Automatic initial references fall back to bare tracking when basis transport is unavailable; incompatible explicit references raise an error.

Use reference_model=nothing, tracking_steps=18 for the original bare tracking. Normal make_model builds default to that bare trajectory, and accept reference_model=initial, tracking_steps=0 for a direct reference match.

Physical rebuilding does not inherit gates. Pass gates=baseline.gates explicitly to sequence fitting and, when needed, prediction. Gate-only updates reuse idle physics; selected gate-parameter paths are explicit updates and remain supported. Use Component(component; operators=...) to extend operators while preserving its derived basis metadata. Six-argument custom construction remains supported.

Timing sequence fits ​

Pass diagnostics=report -> ... to ModelTomographyProblem or predict_sequences to receive timings in seconds after each successful prediction:

julia
reports = []
# Add this keyword to your sequence ModelTomographyProblem call:
# diagnostics = report -> push!(reports, report)
# After evaluating or solving:
# reports[end]

A sequence fit report contains rebuild_seconds, gate_update_seconds, setup_seconds (sequence inputs and subspace), propagation_seconds (all gate builds), gate_seconds (gate-name => seconds pairs), sequence_seconds (sequence multiplication and measurements), total_seconds, and parameters (in physical units). Direct predict_sequences reports omit rebuilding, gate updates, and parameters. The total excludes the reporting callback and loss reduction. Initial constructor validation also produces a report. First-call timings include compilation; compare subsequent evaluations. In threaded runs, individual gate times overlap: compare their wall-clock propagation_seconds rather than summing gate_seconds. Reports arrive on the calling task after gate workers finish. Diagnostics are disabled by default; callback errors propagate to the caller.

Evolution storage ​

Model/gate evolution uses dense Hamiltonian and initial-state matrices by default. Use evolution_kwargs=(; dense=false) to preserve their original storage. The same options apply to numerical(model, gate), get_unitary(model, gate), numerical(model, gate, states), and sesolve(model, gate, initial, times).

For a supplied Hamiltonian, get_unitary(H, duration; dense=true) also converts static matrices or the matrix terms of a QobjEvo to dense storage before solving. Time-dependent coefficients are preserved, and the input Hamiltonian is not modified. Use dense=false to preserve its original storage.
